# Scripted collectors for original LIBERO tasks

## Where the existing original demos come from

LIBERO distributes **human teleoperation demonstrations** for its four suites,
as documented in [the upstream README](../../../LIBERO/README.md).
The upstream [download script](../../../LIBERO/benchmark_scripts/download_libero_datasets.py)
fetches those recordings; it does not generate scripted trajectories.
The upstream [collection script](../../../LIBERO/scripts/collect_demonstration.py)
records a human using a keyboard or SpaceMouse.

LangGap's [dataset merger](../../convert/merge_datasets.py) downloads the
`lerobot/libero` dataset and combines it with extended-task demonstrations.
Those original episodes are imported recordings, not generated by the extended
collectors. The existing `collect/scripted_collect_task10.py` attempts the original
bowl-to-plate task, although its header describes a spatial task. A simulator
check of that script failed on the current environment's low placement motion.

## Coverage

`libero_goal/` contains seven `scripted_collect_<original_bddl_stem>.py` entrypoints,
one for each distinct original used in the nine
[paired task folders](../../data/bddl_files/libero_goal/paired_original_extended/README.md):

| Original | Policy |
| --- | --- |
| Put the bowl on the plate | Rim grasp, lift, release above the plate, retreat |
| Put the bowl on the stove | Rim grasp, lift, place, retreat |
| Put the bowl on top of the cabinet | Rim grasp, high transfer, place, retreat |
| Put the wine bottle on the rack | Neck grasp, lift, rotate onto the sloped rack, release |
| Open the top drawer and put the bowl inside | Stage the bowl on the unlit stove, open the drawer, transfer the bowl into it |
| Open the middle drawer | Hook the handle, pull, disengage, retreat |
| Push the plate to the front of the stove | Close fingers, approach the rim, push along the table, retreat |

This covers the **paired Goal originals**, not all original tasks in all suites.
The representative wine-rack pairing retains the ambiguity documented in
[the mapping](../../data/bddl_files/libero_goal/EXTENDED_TO_ORIGINAL_MAPPING.md).

## Run

From the repository root:

```bash
source activate_env.sh langgap
python langgap/collect/scripted_original/libero_goal/scripted_collect_put_the_bowl_on_the_plate.py \
  --target 50 --num 200 --seed 0 \
  --output langgap/data/source/scripted_original/libero_goal/bowl_on_plate.hdf5
```

Each entrypoint defaults to its canonical original BDDL. `--bddl PATH` accepts a
physically equivalent copy and rejects a different task or scene. The original
BDDLs under `paired_original_extended/` now restore the canonical full scene.
The matched collector below still defaults to the canonical files. Other options:

- `--target` / `--episodes`: successful demos to collect (default 50).
- `--num`: maximum attempts (default 200).
- `--max_steps` / `--max-steps`: recorded action budget per attempt (default 700).
- `--seed`: first attempt's NumPy seed; increments for each attempt.
- `--debug`: one attempt, one requested demo, waypoint diagnostics.
- `--output`: a new HDF5 path; existing files are never overwritten.

For matched original/extended starts, use the combined collector below. The
individual task entrypoints sample independently.

Initial scenes are sampled from the BDDL distribution, followed by ten unrecorded
settling steps. These are independent samples, not matched original/extended
initial states or samples from the official `.pruned_init` banks. The reusable
policy function also accepts an `initialize_scene` callback for a caller that
restores a compatible settled scene.

## Matched original and extended collection

From the repository root:

```bash
./langgap/collect/scripted_original/libero_goal/collect_matched.sh \
  --episodes 5 --max-scenes 40 \
  --output-dir langgap/data/scripted_runs/matched_goal_original_extended
```

This runs the existing matched collector with `--include-originals`: **seven
original tasks plus nine extended tasks, all from each accepted scene**. Shared
originals are collected once per scene. Their IDs are 10, 11, 12, 14, 17, 18, and
19; extended IDs remain 54–57 and 77–81. The pair mapping is recorded in the
manifest and exports, including the representative rack pairing for task 81.

The runner validates that all 16 BDDLs describe the same physical initialization.
It restores a complete settled snapshot before every policy, including fixture
model poses, robot and object positions/velocities, simulation time, integration
inputs, and gripper state, and resets controller goals. It asserts exact restored
state equality, equality of the first recorded state, and initial-camera pixel
equality. `--no-verify-images` skips only the camera check.

A scene is accepted only if **all 16 policies succeed**. A failure rejects the
whole bundle, so separate per-task success filtering cannot misalign the exports.
Insufficient complete bundles produce a nonzero exit and a partial manifest.

Reuse a previous extended run's configurations without modifying its bank:

```bash
./langgap/collect/scripted_original/libero_goal/collect_matched.sh \
  --episodes 5 --max-scenes 40 \
  --scene-bank /path/to/previous/scene_bank.hdf5 \
  --output-dir langgap/data/scripted_runs/matched_goal_reused
```

Match runs by `scene_hash` and `scene_id`, not episode number. Reusing a bank does
not guarantee every original policy succeeds on every old scene; failed bundles
are reported rather than replaced with independently sampled starts. The default
for a new bank is the existing canonical task-54 `.pruned_init` distribution;
`--random-init` samples BDDL starts instead.

Outputs are `matched_demos.hdf5`, `manifest.json`, and 16 `task<ID>.hdf5` files.
Each exported episode includes its shared `scene_id`, `scene_hash`, initial image
hash, fixture poses, and a self-contained `initial_scene` snapshot. The original
standalone exports created earlier are independent and must be recollected through
this runner to obtain matched starts. The existing nine-task training conversion
and evaluation helpers remain configured for nine tasks; this option adds matched
HDF5 collection for all 16 tasks.

Only attempts passing the actual original BDDL success predicate after release
and settling are exported. Drawer opening, staging, rotation, pushing, and retreat
are recorded robot actions; policies do not set object poses or drawer joints.
Collection exits nonzero if it cannot reach the requested count. Any successful
partial export is marked `data.attrs['complete'] = False`.

Outputs use the existing collector HDF5 layout: `data/demo_N/states` holds the
pre-action simulator states, `actions` holds the matching seven-dimensional OSC
actions, and `model_body_pos` / `model_body_quat` preserve fixture poses for replay.
Metadata includes the original BDDL, instruction, environment/controller settings,
body names, attempt seeds, requested episode count, and completion status.
Camera images are produced later by the existing replay/conversion tools.

`policies.py` shares pose, handle-orientation, and HDF5 helpers with the existing
extended collectors. Keep this directory within the repository when running it.

## Validation and replay

Validated on 2026-10-20 in the root `.venv-langgap` environment:

- All seven entrypoints collected and exported a successful demo with a budget
  of three attempts. Six succeeded at seed 0; plate pushing succeeded at seed 1.
- Exported state/action lengths, finite values, action bounds, fixture poses,
  seeds, and completion metadata were checked. Restoring each recorded final
  state and its fixture poses passed the original BDDL goal for all seven tasks.
- Different-task BDDLs and existing output files were rejected. Python compilation
  and documentation links were checked.

These are smoke checks, not estimated success rates over the full distribution.

**Action-only replay is not exact:** replaying from just the flattened initial
state passed five of seven goals; plate pushing and wine-rack placement diverged.
The flattened state omits some controller/integration history. For faithful
rendering of the collected trajectories, restore the episode's `model_body_pos`
and `model_body_quat`, then restore each recorded `states[i]` and call
`sim.forward()` before rendering. `process/replay_dataset.py` runs an action
rollout instead, and can therefore show a different trajectory.
`convert/source_to_lerobot.py` renders stored states, but its generic path currently
does not restore these per-episode fixture arrays; apply those arrays before
using it for these exports. This change adds collectors, not a conversion run.
